PLAN DE INGENIERÍA DE SOFTWARE PARA PROYECTOS
Backend NestJS + Frontend Angular + Azure Infrastructure
============================================================

PROYECTOS:
- PROYECTO PRINCIPAL: BioFincas Monitor (migración a arquitectura separada)
- PROYECTO PARALELO: DigiDeeFree Monitor (implementación)

NUEVA ARQUITECTURA:
- Frontend: Angular 18+ (SPA) → Azure Static Web Apps
- Backend: NestJS (API REST) → Azure App Service
- Base de datos: PostgreSQL → Azure Database for PostgreSQL
- Autenticación: JWT + Session Management
- Manejo de sesiones → Azure Cache for Redis
- Manejo de roles y permisos: RBAC (Role-Based Access Control) + ACL (Access Control List)
- Auditoría: Sistema completo de logs y trazabilidad

MIGRACIÓN DE FRONTEND:
- Estado actual: Next.js 15 + React 19
- Estado objetivo: Angular 18+ con arquitectura modular
- Razón: Mejor arquitectura empresarial, TypeScript nativo, escalabilidad

MODELOS DE DATOS CLAVE
============================================================

-- Tabla de usuarios
CREATE TABLE users (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  first_name VARCHAR(100),
  last_name VARCHAR(100),
  is_active BOOLEAN DEFAULT true,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

-- Tabla de roles
CREATE TABLE roles (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name VARCHAR(50) UNIQUE NOT NULL,
  description TEXT,
  created_at TIMESTAMP DEFAULT NOW()
);

-- Tabla de permisos
CREATE TABLE permissions (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  resource VARCHAR(100) NOT NULL,
  action VARCHAR(50) NOT NULL,
  description TEXT,
  UNIQUE(resource, action)
);

-- Relación usuarios-roles (muchos a muchos)
CREATE TABLE user_roles (
  user_id UUID REFERENCES users(id) ON DELETE CASCADE,
  role_id UUID REFERENCES roles(id) ON DELETE CASCADE,
  PRIMARY KEY (user_id, role_id)
);

-- Relación roles-permisos (muchos a muchos)
CREATE TABLE role_permissions (
  role_id UUID REFERENCES roles(id) ON DELETE CASCADE,
  permission_id UUID REFERENCES permissions(id) ON DELETE CASCADE,
  PRIMARY KEY (role_id, permission_id)
);

-- Tabla de auditoría
CREATE TABLE audit_logs (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES users(id),
  action VARCHAR(100) NOT NULL,
  resource VARCHAR(100) NOT NULL,
  resource_id UUID,
  before JSONB,
  after JSONB,
  ip_address VARCHAR(45),
  user_agent TEXT,
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_audit_logs_user ON audit_logs(user_id);
CREATE INDEX idx_audit_logs_resource ON audit_logs(resource, resource_id);
CREATE INDEX idx_audit_logs_created ON audit_logs(created_at);

     - biofincas_db
     - digideefree_db
     - Ventaja: Aislamiento total, escalabilidad independiente
   
   Opción B - Multi-tenant con discriminador:
     - Tabla: organizations (biofincas, digideefree)
     - Todas las entidades con organization_id
     - Ventaja: Código compartido, menor costo

   - Azure AD B2C o Auth0 como proveedor único
   - Usuarios pueden acceder a múltiples proyectos
   - Roles y permisos por organización

4. INFRAESTRUCTURA:
   - Shared: Key Vault, Redis (con namespaces)
